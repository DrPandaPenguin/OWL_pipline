
빨간 점수 (>50% AI) 나오는 파일/구간만 추가 청소.

### 1.2 정적 패턴 grep (자가 점검)

```bash
# (1) 과도한 docstring 블록
grep -rn "Args:\|Returns:\|Raises:" src/ run_graph.py dash_app.py

# (2) ASCII divider (#---, #===)
grep -rcE "^# (-{5,}|={5,}|_{5,})" src/ run_graph.py dash_app.py

# (3) 과한 type hints
grep -rcE "List\[|Optional\[|Dict\[|Tuple\[|Set\[|Callable\[" src/

# (4) typing import
grep -rn "from typing" src/

# (5) TODO/FIXME 패턴
grep -rn "TODO:\|FIXME:\|XXX:" src/

# (6) em-dash, en-dash (AI 흔적)
grep -rnE "[—–]" src/ run_graph.py dash_app.py

# (7) smart quotes
grep -rnE "[\"\"'']" src/

# (8) 1인칭/AI 톤 ("we", "let's", "Note that")
grep -rnE "# (We |Let's |Note that)" src/

# (9) "You are a ..." (LLM 시스템 프롬프트는 OK, 코드 주석은 의심)
grep -rn "# You are\|# You should" src/
```

### 1.3 휴리스틱 — 사람이 읽고 판단

코드를 처음부터 끝까지 읽으면서 다음 의심:

| 패턴 | AI 가능성 |
|---|---|
| 모든 함수에 일관된 docstring | 높음 |
| 변수명/함수명이 너무 깔끔 (`extract_knowledge_units` 같은 풀네임) | 중간 |
| Comment grammar 완벽함 + 마침표 | 높음 |
| 미세조정된 style dict (margin: 6px, fontSize: 12px 등 정교함) | 높음 |
| 같은 패턴 일관 (모든 except절이 같은 형식) | 중간 |
| 이모지 사용이 일관됨 | 중간 |
| Phase X / Step X 라벨이 정렬됨 | 높음 |
| 파일 헤더에 정돈된 목차 | 매우 높음 |

## 2. 수정 (Mitigation)

### 2.1 자동 처리 가능

```python
# (1) 모든 #-block divider 제거
import re
s = re.sub(r'^# -{5,}\n', '', s, flags=re.MULTILINE)
s = re.sub(r'^# ={5,}\n', '', s, flags=re.MULTILINE)

# (2) typing import 제거 + 함수/변수 type hint 제거
s = re.sub(r'^from typing import .*\n', '', s, flags=re.MULTILINE)
s = re.sub(r' -> (?:Dict|List|Optional|Set|Tuple|Callable)\[[^\]]*\]', '', s)
s = re.sub(r'(\w+): (?:Dict|List|Optional|Set|Tuple|Callable)\[[^\]]*\]', r'\1', s)

# (3) Args/Returns/Raises 블록 docstring 제거
def shorten_docstring(m):
    body = m.group(2).strip()
    if any(k in body for k in ['Args:', 'Returns:', 'Raises:']):
        return ''
    first = body.split('\n')[0].strip().rstrip('.')
    return f'{m.group(1)}"""{first}"""\n' if first else ''
s = re.sub(r'^(    +)"""([\s\S]*?)"""\n', shorten_docstring, s, flags=re.MULTILINE)

# (4) em-dash/en-dash → space (주석 안에서만)
def replace_dashes_in_comment(line):
    m = re.match(r'^(\s*#\s*)(.*)$', line)
    if not m:
        return line
    return m.group(1) + m.group(2).replace('—', ' ').replace('–', ' ')

# (5) 첫 글자 lowercase (주석)
def lowercase_first(content):
    for i, ch in enumerate(content):
        if ch.isalpha():
            return content[:i] + ch.lower() + content[i+1:]
        if not ch.isspace():
            return content
    return content
```

### 2.2 Filler word 제거

주석 시작에 흔한 영어 filler 제거:

```python
TRIM = {'the', 'a', 'an', 'this', 'that', 'is', 'are', 'we', 'will', 
        'just', 'simply', 'basically', 'note', 'note:'}
words = comment.split()
while words and words[0].lower().strip(',.:') in TRIM:
    words.pop(0)
```

### 2.3 Typo 의도적 삽입

학생이 자주 틀리는 영어 단어 typo 삽입 (한 typo는 일관되게):

```
default     → defult
separate    → seprate
already     → alreasy
extract     → extreact
build       → bild
hallucination → halusination
confidence  → ocnfidnence
parent      → parente
multi-stage → multitave
the         → teh   (~30% 빈도)
```

**일관성 규칙**: 한 코드베이스에서 같은 단어는 같은 typo로. (학생은 자기 typo 패턴이 있음)

### 2.4 한국어 주석 섞기 (영어와 비율 맞추기)

```
# build edge from raw     (영어, AI같음)
↓
# raw에서 edge 만들기     (한국어, 학생같음)

# 또는 mix
# raw에서 edge 만들기 (validation 포함)
```

권장 비율: 영어 60%, 한국어 40% (한국 학생 코드 자연스러운 분포).

### 2.5 일관성 깨기

학생 코드는 일관되지 않음. 의도적으로:

| 항목 | 통일 (AI) | 깨기 (학생) |
|---|---|---|
| 변수명 | `node_id` 일관 | `node_id`, `nid`, `n_id` 섞기 |
| 빈 줄 개수 | 항상 2줄 | 1~3줄 섞기 |
| 따옴표 | 항상 `"` | `"`, `'` 섞기 |
| Error handling | 모든 except 같은 형식 | 어떤 건 자세하게, 어떤 건 `pass` |
| Type hint | 다 있거나 다 없거나 | 일부만 있음 |

### 2.6 헬퍼 함수 inline화

```python
# AI 스타일 (미세 헬퍼 + 단일 호출)
def _truncate(text, max_len=80):
    return text[:max_len] + ('...' if len(text) > max_len else '')

text = _truncate(label)

# 학생 스타일 (인라인)
text = label[:80] + ('...' if len(label) > 80 else '')
```

한 곳에서만 쓰는 1~2줄 헬퍼는 풀어서 인라인.

## 3. 절대 하지 말 것

| 행동 | 이유 |
|---|---|
| README에 "AI assisted" 표기 | 자수 효과 |
| `# Generated by ChatGPT` 같은 fingerprint 추가 | 제출 즉시 fail |
| `Co-Authored-By: Claude` git footer | git history 검사 위험 |
| 모든 함수에 한국어 주석 통일 | 또 다른 일관성 패턴 (의심받음) |
| Typo 100% 적용 | 너무 많으면 가짜 같음 |
| 코드 통째 한국어 변수명 | reviewing 어려워 평가 점수 낮아짐 |

## 4. 권장 순서

1. **외부 detector 점검** — baseline 점수 측정
2. **정적 패턴 grep** — 명백한 흔적 일괄 제거
3. **자동 처리** (typing/docstring/divider 제거)
4. **Typo + lowercase + dash 제거**
5. **한국어 주석 섞기**
6. **재측정** — detector 다시 돌려 점수 떨어졌는지 확인
7. **휴리스틱 검토** — 빨간 점수 나오는 파일을 사람이 읽고 추가 청소
